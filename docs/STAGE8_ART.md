# 8단계 준비 — 이미지·UI 소재 점검과 상자 개봉 연출 (2026-11-19)

제작자 요청: 8단계(로그인·선물함·운영자)용 그림·UI 소재를 미리 준비하되 **이미 있는 그림은 다시 만들지 않는다**, 새 그림은 **6단계 아틀라스 화풍**.
8단계 기획서(`dragon-force-stage8-v1.0/index.html`)는 회사 PC에만 있어 이번 점검에서는 읽지 못했다 → 아래 5번은 "기획서에서 채워 줘야 할 항목" 목록이다. 기획서 HTML을 폴더에 넣어 주면 대조해 고친다.

> 그림 파일은 지금 **design/ui 브랜치**(`public/art/`)에만 있고, 게임 본체(main)는 아직 도형 그림을 쓴다. 두 브랜치는 충돌 없이 합쳐진다(시험 병합: 타입 검사·테스트 113개 통과). 그림을 실제 게임 화면에 쓰려면 먼저 design/ui → main 병합이 필요(제작자 결정).

## 4. 그림 대신 코드로 그리는 것(캔버스 안 "CSS·SVG"에 해당)
게임 화면은 HTML이 아니라 Phaser 캔버스라 CSS가 직접 먹지 않는다. 대신 **도형 코드(Phaser Graphics)** 로 그리면 같은 효과를 얻고, 크기·색·등급을 숫자로 바꿀 수 있다. (HTML 페이지인 개인정보처리방침·시안 갤러리만 CSS)
| 코드로(그림 X) | 그림으로 |
|---|---|
| 판·팝업·버튼(두께·눌림)·탭 바·리본 제목·진행 막대·배지·"!" 새 소식·슬롯 | 배경(로비·로그인), 이벤트 배너 그림 부분 |
| **장비·보상 카드 등급 테두리**(등급 5색 + 빛 번짐), 등급 머리띠 | 캐릭터(초상·탑다운), 적·보스 |
| 화면 어둡게·빛줄기·충격파 고리·파티클·화면 진동·번쩍임 | 물건 아이콘(상자·재화·장비·스킬·선물·행동력) |
| 타이머·숫자·모든 글자(번역·수정이 쉬움) | 게임 로고(원하면) |
SVG는 아이콘을 아주 단순하게 할 때만 의미가 있고, 아틀라스 화풍(부드러운 3D 채색)은 SVG로 표현하기 어렵다 → 화풍 그림은 WebP, 장식·틀은 코드.

## 5. 8단계 로그인 · 선물함 · 운영자 — 기획서에서 받아야 할 문구·정책·데이터
지금 게임은 **서버가 없다**(저장은 기기 안, 웹·iOS·토스 공통 `src/platform/store`). 그래서 "로그인·운영자 우편"을 어떻게 할지가 먼저 정해져야 한다.
| 구분 | 필요한 것 |
|---|---|
| 로그인 방식 | ① 게스트만(기기 저장, 지금 구조) ② 애플·토스 로그인 + 서버 저장. ②면 애플 심사상 다른 소셜 로그인을 넣을 때 "Sign in with Apple"도 필요, 개인정보처리방침 개정, 계정 삭제 기능 의무(App Store 5.1.1) |
| 로그인 화면 문구 | 게임 제목, "화면을 터치하세요", 버전 표기, 이용약관·개인정보처리방침 링크 문구, 첫 실행 동의 문구(필요 시), 점검 중 안내 |
| 선물함 정책 | 보관 기간(무기한/30일), 최대 보관 개수, 만료 처리, "모두 받기" 유무, 행동력 40 초과 보류 규칙(이미 확정: 받지 않고 보관), 받은 선물 기록 보관 기간 |
| 선물함 문구 | 제목, 빈 선물함, 받기/모두 받기, 보류 안내("행동력이 가득 차 받을 수 없어요"), 만료 표시("N일 남음"), 받음 알림 |
| 선물 데이터 | 선물마다 `id`(중복 지급 방지 키), 종류(행동력·골드·루비·카드·조각·개봉권), 수량, 제목·내용, 보낸 이("운영자"/"시스템"), 생성·만료 시각, 출처(최초 클리어·출석·보상·운영자) |
| 운영자 시스템 | 서버 없이 하려면 **앱 업데이트에 우편 목록(JSON)을 같이 넣거나**, 공개 주소(GitHub Pages)에서 우편 목록을 읽기. 우편마다 시작·끝 날짜, 대상(전체), 한 사람 한 번(id 기록) — 쿠폰 코드를 쓸지도 결정. 토스·애플 모두 외부 결제·외부 링크 제한 지키기 |
| 보상 표 | 최초 클리어(행동력 20, 확정), 출석·이벤트 보상, 점검 보상, 사과 보상 등 수량 |
| 공지 | 공지 목록(제목·본문·기간), 점검 시간 표시 |

## 6. 상자 개봉 연출 (구현 완료 — main `src/ui/ChestOpening.ts`)
**가능하다.** 그림을 층(본체·뚜껑)으로 나누고, 움직임·빛·파티클·진동·소리는 코드로 만든다. 지금은 도형 임시 상자로 동작하며, 아래 파일이 들어오면 코드 수정 없이 바뀐다.

순서: 어두워짐 → 상자 등장 → **흔들림**(등급이 높을수록 많이·빠르게, 틈새 빛 점점 강해짐) → **뚜껑 열림**(위로 날아가며 회전·사라짐) → **빛·파티클 폭발**(빛줄기·충격파 고리·번쩍임·화면 진동, 희귀 이상은 "희귀!/영웅!/전설!" 글자) → **보상 카드 등장**(기존 결과 화면 카드가 한 장씩 뒤집힘) → 닫기.

| 등급 | 흔들림 | 파티클 | 빛줄기 | 번쩍임 | 진동 | 충격파 |
|---|---|---|---|---|---|---|
| 일반 | 2회 | 18 | — | — | — | — |
| 희귀 | 3회 | 32 | 6 | — | 약 | — |
| 영웅 | 4회 | 48 | 10 | ✅ | 중 | ✅ |
| 전설 | 6회 | 80 | 16 | ✅ | 강 | ✅ |
- 연출 등급 = 결과 중 가장 높은 등급(10회 개봉도 한 번 연출). 골드 상자는 금액 순위(500·1000·2000·5000G → 일반~전설), 특수 스킬 조각은 희귀. 수치는 `src/data/chestFx.ts` 한 곳.
- **보상 안전**: 보상은 버튼을 누르는 순간 `Progress.openBox`가 거래 ID와 함께 확정·저장한 뒤 연출이 시작된다. 건너뛰기(화면 아무 곳·"건너뛰기"·뒤로가기)는 화면만 결과로 넘기고, 화면을 나가면 연출만 지운다 → 보상이 사라지거나 두 번 들어가지 않는다(브라우저 확인: 건너뛰기 2번 눌러도 결과 1번, 연출 중 이탈해도 루비 1번 차감·보상 유지).
