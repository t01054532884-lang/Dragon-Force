# 단계별로 배운 것

게임 개발을 처음 하면서 단계마다 새로 알게 된 개념을 짧게 적는다.

## 1단계 — 전투 프로토타입
### 화면에 드래곤 띄우고 움직이기
- **게임 루프**: 게임은 1초에 약 60번 `update()`를 부른다. 매번 입력을 읽고 → 위치를 바꾸고 → 다시 그린다.
- **Scene(장면)**: Phaser에서 화면 하나 = Scene. `create()`는 처음 한 번(물체 만들기), `update()`는 매 프레임.
- **물리 몸체(body)**: `physics.add.image`로 만들면 속도(velocity)를 주는 것만으로 움직이고, 나중에 충돌 판정도 이걸로 한다.
- **월드와 카메라**: 맵(4000×4000)은 화면(720×1280)보다 크다. 카메라가 드래곤을 따라가고, UI는 `setScrollFactor(0)`으로 화면에 고정한다.
- **방향 벡터 정규화**: 오른쪽+위를 같이 누르면 (1, −1)이라 길이가 1.41 → 대각선이 더 빠르다. `normalize()`로 길이를 1로 맞춘다.
- **터치 조이스틱**: 누른 곳을 중심으로, 끌고 간 거리(최대 90px)를 0~1 세기로 바꿔 속도에 곱한다.
- **도형 텍스처**: `Graphics`로 원·삼각형을 그린 뒤 `generateTexture`로 그림처럼 쓴다. 그림 파일이 없어도 시작할 수 있다.

### 적·공격·체력·죽음
- **데이터와 코드 나누기**: 적 체력·속도·피해를 `src/data/enemies.ts` 표에 모아 두면, 코드를 건드리지 않고 숫자만 바꿔 난이도를 조절할 수 있다(기획자가 수치 표를 만지는 방식).
- **클래스로 적 만들기**: `Enemy`는 물리 이미지에 체력·종류를 붙인 것. 매 프레임 `step()`에서 드래곤 쪽 방향을 구해 그 방향으로 속도를 준다(추적).
- **그룹과 충돌**: 적·화염탄·마력탄을 그룹으로 묶고 `collider`(서로 밀어냄)와 `overlap`(겹치면 함수 실행)으로 규칙을 정한다. 적끼리 collider를 걸어 한 점에 뭉치지 않게 했다.
- **쿨다운 타이머**: "0.6초마다 발사"는 남은 시간에서 매 프레임 `delta`(지난 ms)를 빼다가 0 이하가 되면 쏘고 다시 600으로 채운다. 적 생성·마법사 공격도 같은 방식.
- **무적 시간**: 몸이 겹쳐 있는 동안 매 프레임 피해를 주면 한순간에 죽는다. 맞은 뒤 0.5초 동안은 피해를 무시한다.
- **화면 밖 생성**: 적은 드래곤에서 820px 떨어진 원 위(화면 밖)에서 나와야 갑자기 튀어나오지 않는다.
- **장면 다시 시작**: `scene.restart()`는 `create()`를 다시 부르지만 클래스 필드 값은 남아 있어서, 체력·시간 등을 `create()` 처음에 직접 초기화해야 한다.

## 2단계 — Survivor 시스템 (경험치 → 레벨업 → 3택)
- **게임 상태(mode)**: `play`(전투) / `choose`(카드 고르는 중) / `over`(게임오버) 세 가지로 나누고, `update()`는 `play`일 때만 돈다. 상태를 한 변수로 두면 "카드 고르는 중에 맞아서 죽는" 같은 꼬임을 막기 쉽다.
- **일시정지**: 카드를 고를 때 물리(`physics.pause`)와 타이머(`time.paused`)를 같이 멈춰야 한다. 물리만 멈추면 "1.4초 뒤 화염탄 삭제" 같은 예약 작업은 계속 흘러간다.
- **경험치 곡선**: 다음 레벨까지 필요한 양 = 5 + 4×레벨 + 0.4×레벨². 처음엔 빨리 올라 재미를 주고, 뒤로 갈수록 천천히.
- **보석 끌어당기기(자석)**: 드래곤과 보석 거리가 `magnet`보다 가까우면 보석을 드래곤 쪽으로 날린다. 한번 끌리면 끝까지 따라오게 표시(`pulled`)해 둔다.
- **여러 레벨 한꺼번에**: 큰 보석을 먹으면 레벨이 2~3번 오를 수 있다. 오른 횟수를 `pendingLevelUps`에 쌓고, 카드를 하나 고를 때마다 다음 카드 화면을 연다.
- **카드 뽑기**: 아직 최대 레벨이 아닌 카드만 모아 섞고(피셔–예이츠 셔플) 앞의 3장. 같은 카드가 두 번 나오지 않는다.
- **판마다 새 능력치**: 기본 능력치(`BASE_STATS`)를 복사해서 쓰므로, 카드로 바뀐 값이 다음 판에 남지 않는다. (5단계 영구 강화는 이 기본값을 올리는 방식이 된다.)

## 3단계 — 스킬 시스템
- **스킬 = 쿨다운 + 대상 고르기 + 효과 + 그림**: 6종 모두 같은 틀이다. 쿨다운이 0이 되면 → 대상(가까운 적, 부채꼴 안의 적, 적이 많은 곳)을 고르고 → 피해·둔화를 주고 → 잠깐 보였다 사라지는 그림을 그린다.
- **헛방 방지**: 쏠 대상이 없으면 쿨다운을 다시 채우지 않는다. 적이 나타나는 순간 바로 발동한다.
- **수치는 레벨 함수로**: `SKILL.breath.damage(lv) = 10 + 6×lv`처럼 적어 두면 카드 설명과 실제 효과가 같은 식을 쓰게 돼서, 설명과 효과가 어긋나지 않는다.
- **물리 없이 판정하기**: 얼음 파편·오브·메테오는 물리 몸체 없이 "거리 < 적 반지름 + 내 반지름"으로 직접 맞았는지 계산한다. 적이 수백 마리여도 가볍다.
- **부채꼴 판정(브레스)**: 적까지 거리 ≤ 사거리이고, 적 방향 각도와 드래곤 방향 각도의 차이(−180°~180°로 감싼 값)가 반각 이하이면 부채꼴 안이다.
- **연쇄(번개)**: 맞은 적을 집합에 넣고, 마지막으로 맞은 적에서 가장 가까운 "아직 안 맞은" 적을 찾아 튄다. 집합이 없으면 두 적 사이를 무한히 오간다.
- **계속 닿는 공격(오브)**: 오브가 적 몸에 겹쳐 있는 동안 매 프레임 때리면 순식간에 녹는다. 적마다 "마지막으로 맞은 시각"을 기록해 0.45초가 지나야 다시 때린다(1단계 드래곤 무적 시간과 같은 생각).
- **피해 입구 하나로 모으기**: 화염탄과 모든 스킬이 `damageEnemy()` 한 곳을 거쳐 피해를 준다. 4단계에서 처치 보상·피해 숫자를 붙일 때 한 곳만 고치면 된다.
- **멈출 때 같이 멈추기**: 스킬 시간은 `update()`의 delta로만 흐르게 해서 카드 고르는 동안 같이 멈춘다(2단계의 `time.paused` 교훈).
- **개발 중 화면 갱신(HMR)**: 파일을 하나씩 고치는 사이 브라우저가 먼저 새로 고쳐지면 반쯤 바뀐 코드로 돈다(이번에 `u.apply is not a function`). 여러 파일을 고친 뒤에는 새로 고쳐서 다시 확인한다.

## 3단계 마무리 — 기획서를 코드로
- **피해 계산을 한 곳에**: 최종 피해 = 공격력 × 계수 × 레벨 배율 × 같은 묶음 배율 × 치명타 … (`Damage.ts`). 모든 공격이 이 함수를 거치니, 기획서 표의 숫자를 코드로 그대로 검증할 수 있다.
- **고정 시간 간격으로 시뮬레이션**: 게임을 멈추고 `update(1000/60)`을 직접 반복 호출하면 1분 전투를 순식간에, 매번 같은 결과로 돌릴 수 있다. 밸런스 표를 검증하는 가장 빠른 방법.
- **타이머 오차**: "1.02초마다"를 "남은 시간이 0 이하면 1.02초로 다시 채움"으로 짜면, 프레임(16.7ms)에 딱 안 맞는 만큼 매번 버려져 실제로는 1.033초가 된다. "1.02초를 더함"으로 바꾸면 넘친 시간이 다음으로 이어진다.
- **상태이상 중첩**: 화상은 중첩마다 남은 시간을 따로 들고, 최대 3개. 꽉 차면 가장 오래된 것을 새로 고친다. 평균 중첩 = 지속시간 ÷ 부여 간격(3 ÷ 1.02 ≈ 2.94)이라 평균 화상 DPS = 2.94 × 20 = 58.8.
- **가중치 뽑기**: 유형별 가중치(35/30/15/20)를 더한 범위에서 난수를 뽑고, 후보가 없는 유형은 빼고 다시 계산한다. "몇 레벨까지 안 나오면 보장" 같은 규칙은 뽑기 전에 먼저 한 칸을 채운다.
- **모의 실험으로 규칙 확인**: 카드 1,000판을 코드로 돌려 슬롯 초과·중복·보장 위반을 세면, 손으로 수십 판 하는 것보다 확실하다.

## 4단계 — 스테이지
- **웨이브 표**: "몇 분부터 몇 초마다 몇 마리, 종류 비율"을 표로 두고, 지금 시간보다 이른 것 중 가장 늦은 줄을 쓴다. 난이도 조절 = 표 수정.
- **확률 비율로 고르기**: 0~1 난수에서 비율을 하나씩 빼다가 0보다 작아지는 칸을 고른다(병사 0.4, 슬라임 0.2… 이면 40%·20%…).
- **패턴 = 상태 기계**: 걷기 → 예고(멈춤) → 돌진 → 걷기. 지금 상태와 남은 시간만 기억하면 된다. 예고가 끝난 뒤 "돌진할지, 그냥 걸을지"를 따로 기억하지 않아 보스 범위 공격 뒤에 엉뚱하게 돌진하는 버그를 만들 뻔했다.
- **적은 "하겠다"만, 장면이 "한다"**: 적(`Enemy.step`)은 `{ kind: 'slam', x, y, r }` 같은 행동을 돌려주고, 그리기·피해 판정은 장면이 한다. 적 코드가 화면·플레이어를 몰라도 돼서 깔끔하다.
- **예고 → 판정**: 원형 예고가 차오르는 동안 피하고, 시간이 다 되면 그 순간 원 안에 있는지로 맞았는지 정한다. 피할 수 있어야 재미있다.
- **클리어 보상 식**: 300 + 200 × (남은 시간 비율). 같은 클리어라도 빨리 잡으면 더 받게 해서 성장(5단계)으로 다시 도전할 이유를 만든다.

## 4단계 다시 — 엘리트·보스·클리어
- **상태 머신(스테이지)**: WAVE_1 → ELITE_1 → WAVE_2 → ELITE_2 → BOSS_WARNING → BOSS → CLEAR/FAIL. 타이머는 멈추지 않고, 상태는 "지금 무엇을 보여 줄지"만 정한다. 시간표 숫자(1:40, 3:40, 5:50)는 데이터에 두고 코드는 비교만 한다.
- **동작 대기열(적 패턴)**: 패턴을 [예고 0.8초, 돌진 0.5초, 기절 0.9초]처럼 동작 목록으로 넣고 앞에서부터 하나씩 실행한다. 3연속 돌진도 목록에 6개를 넣으면 끝. 연속 돌진은 각 예고가 시작될 때 그 순간의 플레이어를 다시 노린다.
- **원과 직선의 교점(벽까지 거리)**: 원 중심에서 본 내 위치 o, 방향 d면 벽까지 거리 = −(o·d) + √((o·d)² − |o|² + R²). 철갑어미의 예고선 길이를 이 식으로 구했다.
- **한 방 상한**: 피해 = min(원래 피해, 최대 HP × 35%). 흡수 강화·격노가 겹쳐도 한 번에 죽지 않게 하는 안전장치.
- **시드 난수**: 같은 시드로 만든 난수 생성기는 같은 순서의 숫자를 낸다. 적 생성에 이것만 쓰면 버그가 난 판을 똑같이 다시 볼 수 있다(기획서 완료 기준).
- **이벤트 기록**: stage:start, elite:spawn 같은 이벤트를 시각과 함께 쌓아 두면, "정확히 1:40에 나왔나"를 화면을 보지 않고 숫자로 확인할 수 있다.
- **이름 충돌**: Phaser Scene에는 이미 `events`(이벤트 발신기)가 있어서 같은 이름의 배열을 만들면 타입 오류가 난다 → `stageLog`로 바꿈.

## 5단계 — 영구 성장
- **판 상태 vs 계정 상태**: 레벨·카드·체력은 판이 끝나면 버리고(`RunStats`), 골드·연구소 레벨은 브라우저에 남긴다(`PlayerProgress`). 판을 시작할 때 계정 상태를 한 번 읽어 판 능력치를 만들고, 전투 중에는 바꾸지 않는다.
- **곱하기 vs 더하기**: 영구 +20%와 패시브 +40%를 곱하면 1.68배, 더하면 1.60배. 둘 다 "기본값의 %"로 더하면 강화가 늘어도 수치가 폭주하지 않는다.
- **순수 함수로 계산 분리**: 골드 공식·구매·정산을 화면과 상관없는 함수로 빼면, 게임을 켜지 않고도 "49G로 50G 구매 실패" 같은 규칙을 테스트 21개로 1초 안에 확인할 수 있다(`npm test`).
- **localStorage**: 글자(문자열)만 저장하므로 객체를 `JSON.stringify`로 저장하고 `JSON.parse`로 읽는다. 같은 브라우저·같은 사이트에서만 이어지고, 데이터를 지우면 사라진다.
- **저장 버전과 마이그레이션**: 저장 데이터에 `saveVersion`을 넣어 두면, 나중에 구조가 바뀌어도 "버전 0이면 이렇게 바꾼다"로 예전 기록을 살린다. 4단계 해금 키도 지우지 않고 합쳤다.
- **믿지 말고 보정**: 저장 데이터는 사용자가 고칠 수도, 깨질 수도 있다. 읽을 때마다 음수 → 0, 최대 레벨 초과 → 최대로 맞추고, 아예 깨졌으면 원본을 백업해 두고 처음 상태로 시작한다.
- **중복 지급 막기**: 판마다 고유 번호(`runId`)를 만들고, 보상을 준 번호를 기록해 두면 결과 화면을 다시 열어도 두 번 주지 않는다.
- **연속 클릭**: 구매할 때마다 저장소의 *최신* 골드로 다시 검사하고, 골드 차감과 레벨 증가를 한 번에 저장하면 버튼을 빨리 눌러도 골드가 음수가 되지 않는다.
- **장면(Scene) 여러 개**: 로비·전투·연구소를 따로 만들고 `scene.start('lab')`처럼 오간다. 첫 번째로 등록한 장면이 처음 화면.
- **기획의 역전 찾기**: "30초마다 10G"를 클리어에도 그대로 쓰면, 보스를 일부러 늦게 잡을수록 이득이 된다. 공식은 "플레이어가 이걸로 무엇을 하게 될까"로 한 번 더 본다.

## 5단계 v1.2 — 아이템 드롭
- **누적 확률표**: 0~1 난수 하나를 뽑고 0.10%, 0.28%, 0.40%, 0.50% 경계와 비교하면 "처치마다 한 번, 최대 1종"이 자연스럽게 된다.
- **확률은 많이 돌려서 확인**: 200만 번 뽑아 각 아이템이 설정값 ±5% 안에 드는지 테스트한다. 고정 시드 난수를 쓰면 매번 같은 결과.
- **난수 생성기를 나눈다**: 드롭 판정에 적 생성 난수를 같이 쓰면, 아이템 하나 때문에 그 뒤 적 등장 순서가 전부 바뀐다. 용도별로 난수를 따로 두면 시드 재현이 유지된다.
- **이벤트 대기열**: 상자와 레벨업이 동시에 오면 배열에 순서대로 넣고 앞에서 하나씩 연다. 창을 닫을 때 다음 것을 연다.
- **기획 가정을 숫자로 확인**: "500마리에 2.5개"는 맞아도, 한 판에 2,500마리를 잡으면 12개가 된다. 자동 시뮬레이션으로 한 판에 실제로 몇 마리 잡는지부터 재 봐야 확률이 의미를 가진다.
- **게임 한 프레임 직접 돌리기**: `scene.sys.step(시간, 16.7)`은 물리·타이머·애니메이션·update를 한 번에 진행한다. 물리만 돌리면(`world.step`) 공격 타이머가 멈춰 엉뚱한 결과가 나온다.

## 6단계 — 드래곤 10종
- **정의와 소유를 나눈다**: "블루 드래곤은 얼음탄을 쏜다"(모두에게 같은 정의)와 "내 블루는 Lv.3, 2성"(플레이어 상태)을 다른 곳에 둔다. 정의는 코드 파일, 상태는 저장 데이터.
- **엔진 하나 + 데이터 열 개**: 투사체 수·관통·연쇄·둔화 같은 "부품"을 엔진에 한 번 만들고, 드래곤은 어떤 부품을 몇 레벨에 켜는지만 적는다. 레드 코드를 10번 복사하지 않는다.
- **리팩터링은 숫자로 확인**: 엔진을 새로 짠 뒤 예전 레드 DPS 표(83.3 … 243.1)를 그대로 다시 재서 소수점까지 같으면, 바꾼 게 기존 동작을 깨지 않았다는 증거가 된다.
- **누적 레벨 데이터**: Lv.1 상태에서 시작해 레벨마다 바뀌는 것만 덮어쓰면(`{...이전, ...변경}`), "앞 레벨 효과는 계속 유지" 규칙이 자동으로 지켜진다.
- **뽑기 보장(천장)**: 카운터 두 개를 들고, 뽑기 전에 "이번이 보장 차례인가"를 먼저 본다. 확률이 맞는지는 100만 번, 보장이 깨지지 않는지는 10만 번 돌려 "연속 최대값"으로 확인한다.
- **한 덩어리 처리(트랜잭션)**: 소환권 차감 → 추첨 10번 → 조각 → 카운터를 새 상태 객체에 모두 만든 다음 마지막에 한 번만 저장한다. 중간에 문제가 생기면 저장 자체가 안 일어난다.
- **기대값과 실제 수급 비교**: 전설 하나에 평균 59회인데 얻을 수 있는 소환권이 23장이면, 확률이 맞아도 시스템은 동작하지 않는다. 경제는 "얻는 속도"와 같이 본다.

## 출시 기반 — 한 코드로 웹·iOS·토스
- **플랫폼 창구(어댑터)**: 게임 코드는 `store.getItem/setItem`, `platform.onBack` 같은 공통 함수만 부르고, 실제로 무엇을 쓰는지(브라우저 localStorage, iOS Preferences, 토스 Storage)는 플랫폼 파일이 정한다. 플랫폼이 늘어도 게임 코드는 그대로.
- **빌드 모드**: `vite build --mode toss`는 `.env.toss`를 읽어 `VITE_PLATFORM=toss`가 된다. 코드에서 `import('./toss')`처럼 필요할 때만 불러오면 다른 플랫폼 SDK는 결과물에 안 들어간다.
- **동기 ↔ 비동기 저장**: 게임은 "지금 골드가 얼마?"를 바로(동기) 알고 싶은데, iOS·토스 저장소는 기다려야(비동기) 한다. 그래서 시작할 때 한 번 다 읽어 메모리에 두고, 읽기는 메모리에서, 쓰기는 메모리 + 기기에 같이 한다.
- **안전 영역**: 노치·홈바·토스 닫기 버튼에 게임 버튼이 가리면 누를 수 없고 검수에서 반려된다. 게임 화면 상자(`#game`)를 그만큼 안쪽으로 줄이면 Phaser가 그 안에 맞춰 그린다.
- **앱 안에 넣기 vs 웹사이트 띄우기**: 웹사이트를 띄우는 앱은 고치기 쉽지만 인터넷이 없으면 안 되고 애플 심사(4.2)에서 위험하다. 게임은 빌드 결과(`dist`)를 앱 안에 넣는다.
- **스토어 규칙도 요구사항**: 종료 확인 창, 뒤로가기, 처리방침, 등급 증빙처럼 게임 재미와 상관없는 것도 출시 조건이다. 기능보다 먼저 확인해야 나중에 다시 만들지 않는다.

## 6단계 기획 수정안 v1.2 — 메타 성장·경제
- **덧입히기(오버레이)**: 전투 중 기본 공격 Lv.1~7 데이터는 그대로 두고, 영구 성장이 "탄 +1, 피해 +10%"처럼 바꾸는 값만 위에 덮는다. 영구 Lv.1~4면 덮을 게 없어 원래 객체를 그대로 돌려주므로 예전 DPS가 바뀔 수 없다.
- **적용 순서를 정해 두기**: 탄 추가 → 5발 상한 → 넘친 탄은 피해로 → 관통 → 튕김 → 연쇄. 순서가 코드에 하나로 정해져 있어야 같은 상황에서 늘 같은 결과(결정적)가 나온다.
- **재화를 나누는 이유**: 카드(레벨), 정수(해금), 조각(승급)을 섞지 않으면 "무엇을 하면 무엇이 오르는지"가 분명하고, 교환 손실(50%)로 무한 교환을 막을 수 있다.
- **기간 키**: 일일·주간·월간 초기화는 날짜를 직접 지우는 대신 "2026-11-18", "w2026-11-16"(그 주 월요일), "2026-11" 같은 키를 붙여 기록한다. 키가 바뀌면 자연스럽게 새 기간이 되고, 받은 기록은 키째 남아 중복 지급이 막힌다. 한국 시간은 UTC + 9시간으로 계산한다.
- **거래 ID(멱등성)**: 같은 요청이 두 번 와도(연속 클릭·네트워크 재시도) 같은 ID면 한 번만 반영한다. 실제 결제를 붙일 때는 이 확인을 서버가 해야 한다.
- **전투력은 안내용 숫자**: 실제 DPS가 아니라 능력치를 한 숫자로 줄인 지표다. 지수(0.75·0.35·0.15)를 써서 한 능력치만 올려도 숫자가 폭주하지 않게 한다. 입장을 막지 않고 "권장 이상/도전 가능/성장 권장"만 보여 준다.
- **고정 수치 vs 비율**: 공격력이 10인 게임에서 무기 +5는 +50%다. 표에 적힌 숫자가 어떤 단위(10인지 100인지)를 기준으로 했는지 먼저 확인해야 한다.

## v1.3 — 비율 보너스 · DPS 기준 스킬 · 기간 이벤트
- **고정값 vs 비율**: "+5 공격력"은 약한 드래곤일수록 크게, "+7%"는 모두에게 같은 비율로 붙는다. 기본 능력치가 다른 드래곤 10종에는 비율이 공정하다.
- **보너스 중복 금지**: 전용 액티브 피해를 "DPS × 3초"로 정하면 DPS 안에 공격력·레벨·장비가 이미 들어 있다. 여기에 공격력 보너스를 또 곱하면 두 번 적용된다. 그래서 고정 피해로 넣고 배율을 건너뛴다.
- **틱 순서 버그**: "5초 동안 10번"을 만들 때 "시간이 끝나면 멈춤"을 먼저 검사하면 마지막 10번째가 빠진다. 실측(8발 중 7발)으로 찾았다.
- **기간 이벤트**: 시작·끝을 한국 시간 문자열(`+09:00`)로 적고 숫자 시각으로 비교한다. 끝 시각은 포함하지 않는다(`<`).
- **시드 + 회차 난수**: 룰렛 결과를 "저장된 시드와 몇 번째 회차"로 정하면, 같은 회차를 다시 시도해도 결과가 같고(되돌리기 방지) 테스트로 확률을 검증하기 쉽다.
- **날짜 바꿔 시험하기**: 12월 이벤트를 11월에 시험하려면 게임이 "지금 시각"을 한 함수(`gameNow`)로만 묻게 하고, 개발 모드에서만 주소(`?now=`)로 바꾼다.

## 7단계 — 콘텐츠를 데이터로 늘리기
- **스테이지를 복사하지 않는다**: 적 100여 종을 "행동 5종 + 패턴 12종 + 그림 14종류 + 숫자"의 조합으로 만든다. 새 보스는 패턴 목록만 적으면 된다.
- **예고와 판정을 한 곳에서**: 예고선을 그릴 때 정한 방향·위치를 그대로 판정에 쓴다. 그래야 "보였는데 맞았다"는 억울함이 없다.
- **난수를 용도별로 나눈다**: 1단계 적 생성 난수에 보스 패턴 위치 난수를 섞으면 예전 시드가 재현되지 않는다. `시드:pattern`처럼 따로 둔다.
- **자동 측정의 한계**: 움직이지 않는 봇은 적이 몰려와 보스를 늦게 잡고, 패턴을 피하지도 못한다. 방향을 보는 데만 쓰고, 마지막 판단은 사람 플레이로 한다.
- **성장 상한부터 확인**: 권장 전투력 5,000인데 키울 수 있는 최대가 2,700이면 표가 틀린 것이다. 표를 만들기 전에 "최대로 키우면 몇인가"를 먼저 계산한다.
- **같은 시드라도 결과가 다를 수 있다**: 치명타·빙결처럼 화면 밖 난수를 쓰는 효과가 있으면 판마다 결과가 흔들린다. 한 판 결과로 단정하지 않는다.

## 8단계 준비 — 연출은 층과 코드로
- **그림을 층으로 나누면 움직일 수 있다**: 상자 통그림 한 장은 뚜껑을 열 수 없다. 본체·뚜껑을 같은 크기 캔버스에 제자리로 그려 두면 겹치면 닫힌 상자, 뚜껑만 움직이면 열림.
- **프레임 그림 대신 트윈**: 흔들림·튀어오름·회전은 "시작값 → 끝값을 몇 ms 동안" 하는 트윈으로 만들면 그림 한 장으로 충분하다.
- **결과 먼저, 연출은 나중**: 보상을 먼저 저장하고 연출은 보여 주기만 하면, 건너뛰거나 앱을 꺼도 보상이 사라지거나 두 번 들어가지 않는다.
- **등급 차이는 숫자표로**: 흔들림 횟수·파티클 수·진동 세기만 표로 두면 연출 코드는 하나로 네 등급을 다 만든다.

## 8단계 — 선물함과 서버를 미리 생각하기
- **중복 지급 막기는 "이름표"로**: 선물마다 `clear:쉬움:3`처럼 고유 이름을 붙이고, 한 번 만든 이름은 영원히 기록해 둔다. 같은 이름이 또 오면 무시 → 앱을 다시 켜도, 서버가 같은 요청을 두 번 받아도 1회만.
- **모두 받기는 하나씩 판단**: 행동력이 꽉 차서 못 받는 선물이 있어도 나머지는 받는다. 결과에 "받은 것 / 남긴 것과 이유"를 같이 돌려줘야 사용자가 헷갈리지 않는다.
- **규칙은 순수 함수로 떼어 둔다**: "지금 시각"을 인자로 받는 함수로 만들면 테스트가 쉽고, 나중에 서버(Cloud Functions)로 옮길 때 그대로 가져갈 수 있다.
- **입구를 하나로**: 전투에 들어가는 버튼이 4곳이면 차감 코드도 4번 쓰게 된다. 함수 하나(`enterBattle`)를 거치게 하면 한 곳만 고치면 된다.
- **로그인은 기능보다 규칙이 먼저**: 애플은 다른 회사 로그인을 넣으면 애플 로그인도, 계정을 만들면 앱 안 계정 삭제도 요구한다. 반쯤 만든 로그인보다 지금의 게스트(기기 저장)가 심사에 안전하다.

## 8단계 v2.0 — 소급 지급과 "본 것" 기록
- **소급은 비교로**: "깬 단계 목록"과 "이미 준 선물 이름표"를 비교해 없는 것만 준다. 같은 이름표를 쓰니 몇 번 실행해도 1번만.
- **효과는 상태에 붙인다**: 새 선물 별은 "처음 보는 선물이 있을 때"만. 본 선물 목록을 게임 전체에 기억하면 화면을 다시 열어도 같은 선물로 또 터지지 않는다.
- **안전 여백은 화면이 지킨다**: 닫기 버튼 자리는 화면 배치에서 비우면 된다. 그림 파일마다 여백을 넣으면 아이콘이 한쪽으로 쏠린다.
- **그림 크기와 표시 크기를 나눈다**: `setScale(0.5)`는 그림이 바뀌면 크기가 달라진다. `setDisplaySize(108, 108)`처럼 화면 크기로 정하면 도형 그림·실제 그림 어느 쪽이든 같은 크기.

## 다른 컴퓨터의 커밋과 그림 동기화 (2026-11-20)
- **Git 묶음은 소스 파일과 다르다**: `.bundle`은 개발 커밋 이력을 옮기는 전달물이다. 저장소에 그대로 올리는 대신 가져온 커밋을 기존 main에 연결한다.
- **파일과 이력을 따로 비교한다**: OneDrive에 파일만 새로 들어오고 Git 이력은 옛 상태일 수 있다. 현재 파일을 먼저 보관한 뒤 새 커밋과 대조한다.
- **그림 바이트와 화면 픽셀은 다를 수 있다**: 압축·메타데이터 차이로 해시가 달라도 디코딩한 픽셀이 같을 수 있다. 이번에는 두 가지를 비교하고 현재 가공본 파일을 보존했다.

## 8단계 C — 화면 틀을 하나로 (2026-11-20)
- **공통 틀 = 한 번 고치면 모든 화면이 바뀐다**: 머리줄·제목·하단 탭을 화면마다 따로 그리면 색·위치가 조금씩 달라진다. `screenFrame()` 하나를 부르게 하면 7개 화면이 같은 모양이 되고, 고칠 때도 한 곳만 고친다.
- **화면 공간은 예산이다**: 위 머리줄(약 230px)과 아래 탭(약 150px)을 빼면 내용은 890px. 성장표처럼 자주 안 보는 긴 표는 팝업으로 옮겨 자리를 만든다.
- **"가끔 실패하는 테스트"는 시간을 의심한다**: 같은 함수를 두 번 불러 비교했는데 그 안에 현재 시각이 있으면, 두 번 사이에 1ms가 지나는 순간 다르다. 테스트에서는 시계를 고정(`vi.useFakeTimers`)한다.
- **화면이 안 보이면 브라우저가 그리기를 멈춘다**: 숨겨진 탭은 게임 화면 갱신(requestAnimationFrame)이 느려져 캡처가 한 박자 늦게 나온다. 결과가 이상하면 한 번 더 찍어 본다.
