### 규칙(코드: `src/systems/Stamina.ts` · `src/systems/Mailbox.ts`, 모두 순수 함수)
- 행동력 최대 40, 30분마다 1, **입장 때 5 차감**(실패·포기 환불 없음 — 확정). 입장 지점 4곳(로비 전투 시작 · 연구소 바로 전투 · 결과 화면 다음 단계 · 재도전) 모두 `src/ui/entry.ts`의 `enterBattle` 하나를 거친다. 부족하면 아무것도 바뀌지 않고 "입장 가능까지 남은 시간"을 안내.
- 최초 클리어(난이도·단계별) → 행동력 20 선물, 만료 없음. 선물 id `clear:<난이도>:<단계>`가 중복 방지 키. 지급 기록(`granted`)은 선물이 정리돼도 남아 **두 번 지급되지 않는다.**
- 받으면 40을 넘는 행동력 선물은 받을 수 없고 선물함에 남는다. 모두 받기는 오래된 순으로 하나씩 판단(초안 예시 25/40 + 행동력 20 두 개 → 둘 다 남김, 루비·골드는 받음 — 테스트로 확인).
- 운영자 선물 30일 만료, 받은 선물은 7일 뒤 목록에서 정리(내역 50건 보관).
- **운영자 캠페인(서버 없는 첫 출시용)**: `src/data/campaigns.ts`의 목록을 접속 때 확인해 선물함에 넣는다. `campaign:<id>`로 계정당 1회, 기간·대상(전체 / 특정 시각 이전 가입자) 지원. 지금 목록은 비어 있음(개발 모드 `?dev=1`에만 시험 캠페인 3개). 서버가 생기면 이 목록만 서버에서 받아 오면 된다.

### 브라우저 확인(제작자 플레이 탭과 다른 탭, 자동 브라우저)
- 로비: 맨 윗줄 가운데 `⚡ 40/40 가득` + 막대, 3/40일 때 `+1 20:00` 1초마다 감소. 전투 시작 버튼에 `⚡5`.
- 40에서 전투 시작 → 35로 줄고 전투 화면. 3에서 전투 시작 → 로비에 남고 "필요 5 · 현재 3 · 입장 가능까지 49:58" 안내.
- 선물함: 시험 캠페인 3개(골드 1,000 · 루비 300 · 행동력 20), 행동력 40이라 행동력 선물은 회색 "받기"와 이유 표시. 모두 받기 → "2개 받았어요 / 골드 +1,000G · 루비 +300 / 남겨 둔 선물 1개".
- 상점: 장비·드래곤·골드 상자 개봉 연출이 새 그림으로 열림(뚜껑이 날아가고 결과 카드). 콘솔 오류 없음.

## 3. 계정·서버 설계 (초안 E 6~10, 구현 전)

**권장 순서**: 첫 제출(로그인 없음) → 업데이트 1: Firebase 프로젝트 + 게스트(익명) 계정 + 클라우드 저장 → 업데이트 2: Apple·Google 연동 + 계정 삭제 → 업데이트 3: 서버 재화 검증(Cloud Functions) + 운영 도구.

### 구성
- **Firebase Authentication**: 익명 로그인 = 게스트 UID. 나중에 Apple/Google 계정을 같은 UID에 "연결"(link)해서 데이터 유지.
- **Cloud Firestore** `users/{uid}`: 지금 저장 구조(`PlayerProgress` v4)를 거의 그대로 문서로. 보안 규칙: 본인만 읽기, **재화 필드는 앱이 직접 쓰지 못함**(Functions만).
- **Cloud Functions**(서버 규칙): `claimGift` · `claimAllGifts` · `settleRun` · `openBox` · `spendEntry`. 지금 `Mailbox.ts`·`Progress.ts`의 순수 함수를 그대로 옮겨 쓰도록 이미 분리해 둠. 모든 지급·차감에 작업 ID(`txId`) → 재시도해도 1회.
- **캠페인** `campaigns/{id}`: 지금 `src/data/campaigns.ts`와 같은 모양. 접속 때 대상 캠페인을 선물함에 넣고, 계정당 1회는 `granted`로 막음(지금 규칙 그대로).
- **원격 설정** `config/live`: 행동력 최대·회복·입장 비용, 이벤트 기간. 전투 시작 때 설정 버전 고정(초안 6장과 같음).
- **운영 도구**: 관리자 웹(별도, 앱에 비밀키 없음) + 관리자 계정 별도 인증 + 감사 로그.

### 기존 기기 저장 이전(초안 7장)
1. 첫 로그인 때 서버에 `users/{uid}`가 없으면 → 기기 저장을 검증(`sanitize`)해 1회 올림, 기기에는 백업 키로 복사본 유지, `migratedAt` 기록.
2. 서버에 이미 있으면 → 자동 덮어쓰기·합산 금지, "이 기기 기록 / 서버 기록" 중 선택 화면.
3. 실패하면 기기 저장 그대로 두고 다음 접속 때 재시도.

### 필요한 클라우드 설정(제작자 할 일, 업데이트 1부터)
- Firebase 프로젝트 생성, iOS 앱 등록(`com.dragonforce.game`), `GoogleService-Info.plist`(저장소에 올리지 않음 — Codemagic 비밀 값으로).
- Apple Developer: Sign in with Apple 기능 켜기, 서비스 ID·키.
- Google Cloud: OAuth 클라이언트(iOS).
- 요금제·예산 알림, 백업.
- 개인정보처리방침(`public/privacy.html`) 개정: 수집 항목(UID, 연결한 계정 식별자), 보관·삭제.

# 8단계 v2.0 (2026-11-19) — 답변 반영 · 로비 재디자인 · 그림 5차분

원문: `docs/plan/개발8단계_추가요청서_v2.0.md`(0절 = 질문 5건 답 + 첫 제출 범위, 1~15절 = 연출 전체 명세). 그림 묶음 `Dragon-Force-Stage8-v2.0-assets`(폴더에만).

## 확정(제작자 v2.0 0절)
- **최초 클리어 행동력 20 소급 지급** — 지난 클리어도 각 1회. 반복 클리어는 없음.
- **입장 비용 5 확정**.
- **출시 기념 루비 1,000** — 캠페인 `launch-ruby-1000-v1`, 제목·본문 원문 그대로, 들어온 시각부터 30일, 시험 선물과 분리, `LAUNCH_GIFT_ENABLED` 설정으로 켬. 서버가 없으므로 **이 기기 저장 기준 1회**(앱 삭제·기기 변경까지 막지는 않음).
- **로그인·서버·클라우드·관리자는 첫 제출 이후**. 미연결 로그인 버튼·클라우드 UI는 화면에 넣지 않음.
- 첫 제출 범위 = 필수 A~F(아래 적용 현황표).

## 그림 5차분 처리(`scripts/process_art_batch5.py`)
- 받은 PNG는 **그림마다** 오른쪽 위 18%를 비워 둬서 아이콘·드래곤이 왼쪽 아래로 치우쳐 있었다(선물함 아이콘은 512 캔버스에서 실제 그림이 약 290px). 닫기 버튼 자리는 **화면 배치에서** 피하는 것이라(그림 파일마다 비울 필요 없음), 보이는 부분만 잘라 정사각 가운데로 다시 놓았다 → 아이콘 256, 탑다운 384(기존 규격과 같음). 다음 그림부터는 여백 없이 가운데 정렬로 받으면 된다.
- 타이틀 장식은 전체 배경이 아니라 가운데 섬 모양(보이는 부분 819×1057)이라 그대로 잘라 `title-deco.webp`.
- 상자 빛은 600 캔버스 그대로(밑동 y≈485). 상자 그림과 따로 만들어져 입구에 맞추는 값은 코드에서 상자별로 잼.
