# 기획서 읽는 순서

## 개발 8단계

| 순서 | 문서 | 역할 |
|---|---|---|
| 1 | [개발 8단계 기획안 v1.0 초안](개발8단계_기획안_v1.0_초안.md) | 기반 기획 전문. 로그인·계정·클라우드 저장·선물함·보상 캠페인·관리자·데이터 이전·보안·개발 순서 |
| 2 | [개발 8단계 추가 요청서 v2.0](개발8단계_추가요청서_v2.0.md) | v1.0에 더하는 결정사항과 디자인·애니메이션·전투·보상 연출 명세. 0절은 개발 질문 답변과 첫 제출 범위 |
| 3 | [8단계 개발·검토 기록](../STAGE8.md) | 실제로 구현한 것, 검증 결과, 남은 일과 서버 설계 |
| 4 | [최신 인수인계](../HANDOFF.md) | 이어서 개발할 때 먼저 확인할 현재 상태와 우선순위 |

v2.0은 독립적인 전체 기획서가 아니라 v1.0을 보완하는 추가 요청서다. 두 기획서를 함께 읽는다.

## 적용 기준

- v1.0 전문은 당시 작성한 초안 기록으로 보존한다. 날짜·일정·기술·정책 설명이 현재 상태를 자동으로 뜻하지 않는다.
- 명시적인 변경·확정 사항은 v2.0을 우선 적용한다. 첫 제출 범위는 특히 **v2.0 0.5절**을 따른다.
- 예를 들어 v1.0의 로그인·서버 시스템은 장기 설계이고, v2.0에서는 첫 제출 이후 업데이트로 미루었다. v1.0이 저장소에 추가되었다는 이유로 첫 제출 범위를 다시 늘리지 않는다.
- 실제 구현 여부는 `STAGE8.md`, 최신 진행 우선순위는 `HANDOFF.md`에서 확인한다. 기획에 있다는 이유만으로 구현 완료로 간주하지 않는다.
- 기획·구현의 충돌을 발견하면 기존 프로젝트 지침대로 검토·보고하고, 근거 없이 과거 수치나 기능으로 되돌리지 않는다.
