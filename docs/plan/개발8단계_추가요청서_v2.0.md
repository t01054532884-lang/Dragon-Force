## 0. 최신 개발 보고에 대한 답변 및 첫 제출 범위

### 0.1 보고 수용 및 적용 원칙

행동력 진입 경로 4곳 연결, 로비 행동력·선물 배지, 선물함 개별·일괄 수령 및 내역, 저장 v4, 개발용 선물, 테스트 130개 통과는 개발자가 보고한 완료 항목으로 기록한다. 이 문서 작성자가 해당 저장소에서 재검증한 결과는 아니다. 기존 완료 기능을 다시 만드는 대신 아래 결정과 추가 연출을 이어서 적용한다.

### 0.2 질문 1 — 최초 클리어 행동력 20과 선물함 이펙트

**스테이지·난이도별 최초 클리어 시 행동력 20을 선물함에 보내는 방식으로 진행한다.** 직접 행동력 잔액에 더하지 않는다. 같은 스테이지를 반복 클리어할 때마다 20을 추가 지급하는 규칙은 아니다.

- 기존 요청에 포함되어 있던 **과거 최초 클리어 기록의 미지급 보상도 각 1회 소급 지급**한다. 현재 미지급 설정은 기존 요청에 맞게 수정한다.
- 최초 클리어 기록과 지급 기록을 비교하고, 이미 보상 ID가 있는 경우에는 지급하지 않는다.
- 기존 지급 ID가 있으면 그대로 재사용한다. 새 ID가 필요하면 난이도와 스테이지가 포함되는 안정적인 ID를 사용하고, 앱 업데이트·재실행으로 바뀌지 않게 한다.
- 기존 행동력 상한과 수령 가능한 양을 확인하는 규칙은 유지한다. 공간이 없으면 선물함에 남긴다.

**선물이 있을 때 선물함 아이콘 위에 알림 이펙트를 추가한다.**

| 상태 | 표시 |
|---|---|
| 새 선물 도착 | 아이콘 위 작은 금빛 별 3~5개가 600ms 동안 1회 확산, 배지 갱신 |
| 미수령 선물 있음 | 아이콘 상단의 작은 빛과 외곽 빛이 2.4~3.0초 주기로 약하게 밝아짐 |
| 미수령 0개 | 별·외곽 빛·숫자 배지 제거 |
| 일부 선물만 수령 가능 | 미수령 선물이 남아 있으면 빛과 배지 유지. 수령 가능을 보장하는 표현은 사용하지 않음 |
| 선물함을 연 상태 | 카드 읽기를 방해하지 않게 반복 장식은 정지 |
| 모션 감소 | 움직이는 별 대신 정적인 작은 금빛 표시와 숫자 배지 |

빛은 선물함 위쪽의 작은 영역에 제한하고, 상단 닫기 버튼·다른 재화 표시·터치 영역을 덮지 않는다. 매 프레임 이펙트 객체를 새로 만들지 않고 기존 미수령 상태 변화에 연결한다. 화면 복귀 시 같은 새 선물을 계속 신규 도착처럼 폭발시키지 않는다.

### 0.3 질문 2 — 입장 비용

**행동력 5로 확정한다.** 보고된 4개 입장 경로에서 동일하게 적용하고, 화면에 표시되는 비용도 5로 통일한다. 부족 시 표시하는 입장 가능 예상시간과 기존 행동력 판정의 일치 여부만 회귀 검수한다.

### 0.4 질문 3 — 출시 기념 선물

**출시 기념 선물은 루비 1,000개다. 선물함에서 1회 수령하는 방식으로 등록한다.**

| 항목 | 지정 값 |
|---|---|
| 선물 제목 | Dragon Force 출시 기념 선물 |
| 본문 | 드래곤 특공대의 첫 모험을 함께해 주셔서 감사합니다! 출시 기념 루비 1,000개를 받아 주세요. |
| 내용물 | 루비 1,000개 |
| 캠페인 ID 제안 | `launch-ruby-1000-v1` — 기존 명명 체계가 있으면 동일 의미의 고정 ID 사용 |
| 대상 | 출시 선물이 활성화된 빌드의 기존·신규 플레이어 |
| 지급 시점 | 정식 출시용 설정 활성화 후 최초 접속 시 선물함에 등록 |
| 중복 방지 | 기존 캠페인·선물 지급 기록으로 동일 프로필에 1회만 등록·수령 |
| 만료 | 개별 선물 도착 시각부터 30일, 화면에 만료 시각 표시 |

첫 제출은 아래 0.5절에 따라 로그인·서버를 포함하지 않는 범위다. 따라서 현재 버전은 **기기 내 로컬 프로필의 지급 기록에 근거한 1회 제한**이며, 서버 계정·재설치·기기 변경을 아우르는 전역 중복 방지는 제공하지 않는다고 보고한다. 존재하지 않는 서버 계정 검증을 완료했다고 표현하지 않는다.

현재 운영자 선물은 앱 내 캠페인 목록을 읽는 방식이므로 이 목록의 변경은 해당 빌드 배포와 연결된다. 서버 없이 관리자 화면에서 전체 사용자에게 즉시 발송할 수 있는 것으로 설명하지 않는다. 시험용 3개 선물과 정식 출시 선물은 분리한다. 출시 활성화는 명시적인 설정으로 관리하고 개발용 실행만으로 정식 선물을 반복 생성하지 않는다.

### 0.5 질문 4·5 — 첫 제출과 이후 업데이트

**권장 결정: 로그인·클라우드 저장·서버 보상·관리자 시스템은 첫 제출 이후 업데이트로 미룬다.** 이번에는 현재의 게스트·로컬 저장 흐름과 기존 구현을 안정화한다. 미연결 로그인 버튼, 사용 가능한 것처럼 보이는 클라우드 복원·서버 발송 UI는 첫 제출 화면에 노출하지 않는다. 해당 기능을 삭제하라는 뜻이 아니라 준비 상태에 맞춰 비활성 경로를 숨기는 것이다.

이 결정은 기존 iOS 실행 구조에서 계정 연동·데이터 이전을 충분히 검증하기 위한 범위 조정이다. 실제 출시 일정과 코드 접근 여부가 확인되지 않았으므로 특정 날짜의 제출 완료를 약속하지 않는다.

| 우선순위 | 첫 제출 전 범위 | 완료 기준 |
|---|---|---|
| 필수 A | 0절 보상 결정·선물함 알림 효과 | 소급·신규·반복·재진입 시 보상 중복 없음, 배지·이펙트 상태 일치 |
| 필수 B | 로비 재디자인 | 현재 드래곤·주요 진입 버튼·재화·기존 메뉴를 읽기 쉽게 통일, 실제 게임에서 진입 가능 |
| 필수 C | 상점·장비·드래곤의 공통 UI 정리 | 버튼·탭·패널·폰트·등급 프레임·아이콘·간격 통일, 기존 조작 정상 |
| 필수 D | 레드 전투 핵심 연출 | 발사·적중·피격·처치·레벨업이 명확하고 적 공격을 가리지 않음 |
| 필수 E | 대표 상자 개봉 핵심 연출 | 본체·뚜껑·빛·결과 표시·최소 사운드 연결, 스킵·중단 복귀 정상 |
| 필수 F | 모바일·실행 빌드 검수 | 화면 잘림·터치 불가·사운드 오류·중복 지급·중대한 성능 저하 없음 |
| 후속 확장 | 10종 전체의 개별 고급 연출, 추가 배경 레이어·완전한 날갯짓, 모든 화면의 전용 고급 연출 | 본문의 V-4 확장 기준에 따라 업데이트 |
| 후속 서버 | 로그인·서버·클라우드·관리자 | 기존 8단계 초안의 별도 구현·검수 범위 |

상점·장비·드래곤은 제출 전 공통 스타일 적용과 사용성을 우선하고, 각 화면의 전용 고급 애니메이션까지 모두 끝내야 제출할 수 있다고 해석하지 않는다. 필수 D·E도 우선 작고 안정적인 효과로 완성하며 본문의 고급 장식·등급별 최대 효과 수가 모두 제출 필수는 아니다. 제출 직전에 저장·경제 구조를 크게 바꾸지 않는다.

1~15절은 **첫 제출 핵심 적용 + 이후 시각 확장**의 전체 명세다. 필수 범위와 후속 확장 범위를 완료 보고에 따로 표시한다. 긴급 결함이 있으면 장식의 수·복잡도를 줄일 수 있으나 미구현 항목을 완료로 처리하지 않는다.

### 0.6 이번 그림 전달 목록

그림은 `Dragon-Force-Stage8-v2.0-assets` 묶음으로 제공한다. 모든 최종 PNG는 투명 배경이며 오른쪽 위 닫기 버튼 영역을 비워 사용한다. 원본·실행용 파일, 크기·투명도 검수 결과와 실제 파일명은 함께 전달하는 `README`·`manifest`를 기준으로 한다.

- 선물함 아이콘·행동력 아이콘: 각각 512×512.
- 로그인·타이틀용 투명 배경 장식: 1080×1920. 불투명한 전체 화면 배경이 아니라 기존 화면 바탕 위에 올리는 장식 레이어다.
- 한글 가로 로고: “드래곤 특공대”.
- 겨울 축제 배너: 1360×400.
- 스톤·워터 탑다운 드래곤과 패시브 탐욕 아이콘.
- 선택 보완 자료: 상자 내부 빛 3종, 각각 600×600. 상자 원본이 이번 작업 공간에 없으므로 실제 상자와의 중심·회전축 정합은 개발자가 연결 시 확인한다.

공식 Apple·Google 로그인 버튼은 제작 목록에 포함하지 않는다. 그림 전달은 게임 파일에 연결·빌드·배포가 끝났다는 의미가 아니다.

## 1. 추가 목표와 결과물

### 1.1 목표

화면을 켰을 때부터 로비, 버튼 터치, 전투, 보상 획득까지 하나의 게임처럼 보이게 만든다. 정적인 그림 교체에 더해 움직임, 깊이감, 터치 반응, 타격 피드백, 사운드를 실제 게임에 연결한다.

참고 대상은 사용자가 전달한 **궁수의 전설2**의 전반적인 모바일 게임 완성도다. 이 문서는 해당 게임의 내부 구조나 실제 연출 시간을 분석한 문서가 아니다. 특정 화면·아이콘·캐릭터를 그대로 복제하지 않고 Dragon Force의 드래곤 세계관과 기존 아틀라스 화풍으로 제작한다.

참고 링크: https://play.google.com/store/apps/details?id=com.xq.archeroii&hl=ko

### 1.2 반드시 제출할 결과물

| 결과물 | 제출 기준 |
|---|---|
| 실제 게임 빌드 | 게임의 기존 로비와 전투 진입 경로에서 동작하는 빌드 |
| 대표 로비 | 배경·드래곤 대기 동작·공통 UI·터치 반응을 적용한 화면 |
| 대표 전투 | 레드 드래곤의 발사·적중·피격·처치·레벨업·최종 강화 연출 |
| 대표 상자 개봉 | 닫힌 상자부터 개봉·보상 카드·결과까지 이어지는 연출 |
| 공통 스타일 | 색·타이포·간격·버튼·패널·등급 프레임의 재사용 가능한 정의 |
| 영상·스크린샷 | 실제 빌드에서 녹화·캡처한 검수 자료 |
| 적용 현황표 | 구현·임시·미적용·추가 에셋 필요 항목을 구분한 목록 |

문서용 HTML, 별도 이미지 시안, 디자인 전용 페이지는 보조 자료다. 이것만 제출하고 실제 게임 반영을 완료로 처리하지 않는다.

### 1.3 이번 작업에서 지킬 경계

- 기존 기능의 동작·해금 조건·재화·성장 수치·드롭·전투 판정은 기존 요청대로 유지한다.
- 시각적 개선을 이유로 확률, 공격속도, 공격 범위, 보상량을 바꾸지 않는다.
- 실제 게임 엔진과 렌더링 구조를 확인한 뒤 현재 구조에 맞춰 구현한다. 이 작업만을 위해 엔진을 교체하지 않는다.
- 재사용할 수 있는 기존 그림과 코드는 유지하고, 완성도가 부족하거나 움직임에 필요한 부분만 보완한다.

## 2. 대표 화면 3개를 먼저 완성하는 개발 순서

### 2.1 단계별 작업

| 순서 | 추가 작업 | 제출물 | 다음 단계 조건 |
|---|---|---|---|
| V-0 | 현재 게임의 화면·에셋·연출 구현 상태 확인 | 현재 빌드 캡처, 재사용 목록, 부족 에셋 목록 | 기존 구현과 신규 작업의 차이 명확화 |
| V-1 | 공통 스타일과 실제 로비 1개 완성 | 로비 빌드·영상·상태별 버튼 캡처 | 로비 시각 검수 통과 |
| V-2 | 레드 드래곤 전투 연출 완성 | 동일 전투 구간의 적용 전후 영상 | 타격감·가독성·성능 검수 통과 |
| V-3 | 상자 개봉 공통 시스템과 대표 상자 완성 | 일반·전설 결과 연출, 스킵·중단 재진입 영상 | 연출·보상 표시 연결 검수 통과 |
| V-4 | 승인된 스타일을 기존 화면과 드래곤 10종에 확장 | 화면별·속성별 적용 목록 | 전체 스타일 일관성 확인 |
| V-5 | 실제 모바일 기기에서 통합 검수 | 성능·화면·사운드 결과표 | 최종 체크리스트 통과 |

V-1~V-3을 대표 품질로 만든 뒤 V-4의 고급 확장을 진행한다. 첫 제출 전 필수 범위는 0.5절을 우선하며, 기존 화면의 공통 스타일 정리는 병행할 수 있다. 임시 수준의 화면을 전체에 먼저 복제해 놓고 시각적 완성 단계가 끝났다고 보고하지 않는다. 대표 품질 검수 결과를 기다리는 동안 에셋 정리·공통 컴포넌트 작업은 계속할 수 있다.

### 2.2 V-0에서 확인할 내용

- 실제 로비·전투·상자·보상 결과를 그리는 코드와 실행 경로.
- 현재 UI와 전투에 사용하는 렌더링 방식, 애니메이션 처리 방식.
- 6단계 아틀라스와 현재 게임에 연결된 드래곤 이미지의 일치 여부.
- 이미 존재하는 드래곤 대기·날갯짓·공격·피격·개봉 효과.
- 실제로 사용할 수 있는 에셋과 단순 콘셉트 이미지 구분.
- 색상·간격·폰트·등급 색·아이콘의 현재 불일치.
- 사운드 파일·음량 설정·모션 설정·기기 진동 연결 여부.

확인되지 않은 부분은 추정으로 완료 처리하지 않는다. 개발자가 접근 가능한 코드와 빌드에서 확인한 결과를 적는다.

## 3. 공통 아트·UI 스타일

### 3.1 시각 방향

**귀여운 판타지 드래곤 + 선명한 색 + 부드러운 입체감 + 짧고 명확한 반응.**

- 기존 드래곤 아틀라스의 둥근 형태, 큰 눈, 속성 색, 부드러운 조명을 기준으로 한다.
- 인게임 UI는 어두운 남청색 바탕에 밝은 본문과 금색 주요 행동 버튼을 조합한다.
- 로비에는 드래곤 둥지·비행 섬·성채 중 기존 시안과 맞는 하나의 배경 콘셉트를 선택한다. 화면마다 서로 다른 세계관 배경을 섞지 않는다.
- 배경의 대비·채도를 낮춰 캐릭터와 버튼이 먼저 보이게 한다.
- 버튼과 패널의 그림자·테두리·모서리·광원 방향을 통일한다.
- UI 텍스트와 숫자는 실제 텍스트로 표시한다. 이미지에 숫자·가격·버튼 문구를 그려 넣지 않는다.

## 4. 반응형 화면과 공통 컴포넌트

### 4.1 모바일 구성

- 기본 설계 화면: **390 × 844 논리 px, 세로**.
- 필수 확인 폭: **360 / 390 / 430 논리 px**.
- 짧은 화면: **360 × 640**에서 핵심 버튼과 팝업 닫기 조작 가능.
- 노치·상하 시스템 영역을 고려해 상단 정보와 하단 버튼에 안전 여백 적용.
- 태블릿·넓은 웹 화면은 콘텐츠 폭을 제한하고 배경을 확장한다. 모바일 UI를 가로로 무제한 늘리지 않는다.
- 스크롤 영역과 고정 버튼을 구분해 마지막 카드가 하단 메뉴에 가려지지 않게 한다.
- 기존 가로 화면 지원 정책이 있으면 유지하고, 없으면 이번 추가 범위에서 가로 전용 레이아웃을 새로 만들지 않는다.

### 4.2 버튼의 상태와 동작

| 상태 | 추가 시각 처리 |
|---|---|
| 기본 | 위쪽 밝은 면·아래쪽 얕은 그림자·명확한 문구 |
| 누르는 중 | 60~80ms 동안 0.97배 축소, 그림자 감소 |
| 손을 뗌 | 100~140ms 동안 원래 크기, 한 번만 복원 |
| 선택됨 | 테두리·아이콘·문구 강조, 선택 표시 유지 |
| 비활성 | 채도·장식 대비 감소, 비활성 이유는 텍스트로 확인 가능 |
| 처리 중 | 버튼 폭 유지, 짧은 진행 표시, 기존 중복 실행 방지와 연결 |
| 성공·오류 | 결과에 맞는 짧은 표시와 문구, 무한 반짝임 없음 |

터치 영역은 최소 **44 × 44 논리 px**로 설계한다. 작은 닫기 아이콘도 실제 터치 영역은 확보한다. 모바일에서 마우스 호버에만 정보를 숨기지 않는다.

### 4.3 패널·탭·팝업·리스트

- 패널: 1~2px 시각 테두리, 낮은 그림자, 제목·본문·행동 영역 구분.
- 탭: 활성 탭에 명확한 선택 표시, 전환 중 재화·목록이 빈 화면으로 번쩍이지 않게 한다.
- 팝업: 배경 딤 45~60%, 140~180ms 진입, 100~140ms 닫힘. 위치 이동은 8~12px 이내로 제한한다.
- 결과 팝업을 연속 호출할 때 이전 팝업·가림막·입력이 겹치지 않게 한다.
- 리스트: 선택 카드만 짧게 반응하고 정렬·필터 시 카드 전체가 매번 튀어나오지 않게 한다.
- 로딩: 해당 콘텐츠 영역에 로딩 표시. 기존 목록을 아는 경우 즉시 모두 지우지 않는다.
- 빈 목록·오류·재시도: 공통 그림·문구·버튼 스타일 적용. 관리자용 오류 코드나 내부 경로를 화면 중심에 노출하지 않는다.

## 5. 로비의 추가 시각 명세

### 5.1 시선 순서

로비는 **현재 드래곤 → 진입할 스테이지 → 시작 버튼** 순으로 눈에 들어오게 한다. 기존 로비의 정보와 기능을 이 순서에 맞춰 시각적으로 정리한다.

| 영역 | 추가 디자인·연출 |
|---|---|
| 배경 | 전경·캐릭터 영역·후경을 나눈 깊이감. 버튼 뒤는 복잡도를 낮춤 |
| 상단 정보 | 공통 높이·여백의 재화 패널, 아이콘 크기·숫자 기준선 정렬 |
| 중앙 드래곤 | 발밑 그림자, 속성별 약한 빛, 대기 동작. 단순 초상 확대와 구분 |
| 진행 정보 | 스테이지 이름을 1순위, 보조 숫자를 2순위로 배치 |
| 핵심 버튼 | 한눈에 구별되는 금색 계열, 충분한 터치 영역, 짧은 반응 |
| 기존 메뉴 | 동일한 아이콘 화풍·프레임·라벨 간격·선택 상태 |
| 알림 배지 | 메뉴 아이콘 모서리에 고정, 자릿수 증가에도 레이아웃 유지 |

### 5.2 드래곤 대기 동작

- 호흡: 한 주기 2.8~3.6초, 상체 또는 몸통 변화 1~2% 이내.
- 날개: 프레임 또는 분리 레이어가 있으면 2.4~3.2초 주기로 작게 움직인다.
- 날개 자료가 없으면 드래곤 전체를 상하 2~4px 움직이는 임시 대기를 적용할 수 있다. 이를 정식 날갯짓 완료로 보고하지 않는다.
- 눈 깜빡임: 대응 에셋이나 눈 레이어가 있을 때만 4~7초 간격으로 적용. 단일 평면 이미지를 무리하게 변형하지 않는다.
- 발밑 그림자: 캐릭터 움직임에 맞춰 크기·투명도를 소폭 변화시킨다.
- 속성 입자: 드래곤 주변 4~8개를 초기값으로 사용하고, 글자·메뉴와 겹치지 않게 한다.
- 캐릭터 변경: 이전 캐릭터가 짧게 페이드아웃한 뒤 새 캐릭터가 등장. 미보유·미선택 캐릭터가 현재 출격 캐릭터처럼 보이지 않게 기존 상태와 연결한다.

### 5.3 배경과 상호작용

- 빛줄기·구름·먼지 중 1~2개만 느리게 움직인다. 배경 전체를 계속 확대·축소하지 않는다.
- 드래곤을 터치했을 때 250~400ms의 짧은 반응과 작은 속성 입자를 1회 재생한다.
- 같은 캐릭터 반복 터치의 반응은 최소 1초 간격으로 제한한다.
- 재화 수가 변경되면 180~300ms 숫자 전환 또는 짧은 하이라이트를 사용한다. 실제 확정된 값에 수렴해야 한다.
- 모든 메뉴에 지속적인 반짝임을 넣지 않는다. 주요 버튼·현재 선택·실제 알림을 구분한다.

### 5.4 로비 시각 검수

- 360px 폭에서 상단 수량이 겹치지 않는다.
- 작은 화면에서도 드래곤 얼굴·현재 스테이지·시작 버튼이 확인된다.
- 배경을 가린 상태에서도 정보 구조가 이해되고, 배경을 켜도 글자가 읽힌다.
- 대기 30초 동안 움직임이 끊기거나 위치가 누적 이동하지 않는다.
- 데이터가 늦게 도착해도 드래곤·수량이 불필요하게 두 번 등장하지 않는다.

## 6. 기존 앱 내 화면의 추가 디자인 명세

아래는 해당 화면의 기존 기능을 다시 요청하는 표가 아니다. 이미 있는 화면에 추가할 시각 처리다.

| 화면 | 추가 디자인 | 추가 모션·피드백 | 제출 캡처 |
|---|---|---|---|
| 상점 | 상품 그림·등급 프레임·가격·주요 버튼 정렬 | 선택 시 프레임 반응, 요청 중 정지 상태 | 기본·선택·처리 중·재화 부족 |
| 장비 | 슬롯·아이콘·강화 수치의 계층 정리, 장착 표시 통일 | 장착 슬롯 하이라이트 200ms, 실제 강화 성공 시 400~600ms 연출 | 장착·미장착·강화 성공·실패 |
| 드래곤 | 초상과 전투용 이미지의 역할 구분, 속성·등급·별 배치 통일 | 선택 전환, 실제 성장 성공 후 수치 변화 강조 | 선택·잠금·성장 결과 |
| 승급 표시 | 별 등급 가독성, 변경된 특성 강조 | 새 별 점등 300ms, 전체 성공 연출 800~1,200ms | 승급 전후 |
| 연구소 | 능력 카드·현재 수치·다음 수치 간격 통일 | 성공한 카드만 짧은 빛, 최대 단계의 명확한 표시 | 일반·최대·성공 |
| 선물함 | 보상 아이콘·수량·만료·받기 버튼 정렬 | 수령 성공 카드 180ms 제거 후 배지·수량 갱신 | 기본·부분 수령·빈 목록 |
| 이벤트·보상 | 배너와 공통 UI 화풍 연결, 긴 문구 줄바꿈 | 실제 수령 성공 시 짧은 공통 보상 연출 | 미수령·수령 완료 |
| 로그인·설정 | 기존 인증·설정 기능 주변 패널·배경 스타일 통일 | 처리 중·연결 실패·완료 상태의 명확한 전환 | 기존 연결 가능한 상태 기준 |
| 결과 화면 | 성공·실패 구분, 결과 숫자의 시각적 우선순위 | 제목 → 요약 → 보상 순으로 600~900ms 내 표시 | 클리어·실패·보상 없음 |

기존에 존재하지 않는 화면의 신규 기능 구현은 이 표로 추가 승인한 것으로 해석하지 않는다. 로그인 제공자 버튼은 기존에 채택한 공식 리소스·구성 규칙을 유지하며, 이번 작업에서 임의의 게임용 모양으로 다시 그리지 않는다.

## 7. 레드 드래곤 전투 연출

### 7.1 우선 완성할 전투 구간

현재 게임에서 레드 드래곤으로 진입 가능한 대표 스테이지 하나를 선택한다. 고정된 시드·성장·장비·스킬 조건을 기록하고 같은 조건의 적용 전후 영상을 비교한다. 현재 최신 저장·밸런스를 기준으로 하며, 과거 기획서의 수치로 되돌리지 않는다.

다음 시간은 **공격 판정이 발생한 시점을 기준으로 하는 시각 효과 시간**이다. 공격 주기나 판정 시각을 이 시간에 맞춰 늦추지 않는다.

### 7.2 발사 → 이동 → 적중

| 이벤트 | 추가 연출 | 초기 제안 값 | 판정과의 관계 |
|---|---|---|---|
| 공격 발생 | 입·발사점 섬광, 짧은 캐릭터 반응 | 섬광 60~90ms, 반응 80~120ms | 기존 발사 이벤트에서 재생 |
| 화염탄 이동 | 밝은 중심·주황 테두리·짧은 꼬리 | 꼬리 4~8조각 또는 길이 제한 트레일 | 기존 투사체 위치 추종 |
| 일반 적중 | 작은 충격 링·불꽃 파편 | 120~180ms, 파편 4~8개 | 적중 이벤트에서 재생 |
| 적 피격 | 짧은 밝기 변화, 기존 넉백이 있으면 동기화 | 피격 표시 60~90ms | 새 넉백 판정 추가 금지 |
| 치명타 | 일반 타격과 다른 숫자·작은 강조 | 숫자 1.15~1.25배, 추가 빛 80ms | 실제 치명타 결과만 표시 |
| 화상 | 적 주변 작은 불씨·상태 아이콘 | 동시 불씨 2~4개, 약한 지속광 | 실제 상태 지속·종료를 따름 |
| Lv.7 폭발 | 중심 플래시·충격 링·불꽃 | 220~320ms, 파편 8~12개 | 실제 폭발 이벤트와 범위 기준 |

표시 범위를 실제 피해 범위보다 크게 부풀려 공격 판정을 오해하게 만들지 않는다. 투사체 수가 늘어도 발사점이 맞고, 공격이 겹칠 때 불꽃이 화면을 덮지 않게 한다.

### 7.3 숫자와 타격 피드백

- 피해 숫자는 기존에 표시하는 피해 결과에서 생성한다. 연출용 피해값을 별도로 계산하지 않는다.
- 일반 피해는 밝은 중립색, 치명타는 금색과 별도 표식으로 구분한다.
- 떠오름 18~28 논리 px, 450~650ms 내 소멸. 동일 위치 숫자는 약간 분산한다.
- 같은 대상의 동일 지속 피해가 과도하게 겹치면 150~250ms 시각 구간으로 합산할 수 있다. 합산은 표시만 바꾸고 실제 피해 처리는 그대로 둔다.
- 일반 적 타격마다 화면 흔들림·시간 정지를 발생시키지 않는다.
- 드래곤의 발사 반동은 시각 레이어에만 적용한다. 이동 좌표·충돌체·조준 원점이 반동 때문에 달라지지 않게 한다.

### 7.4 드래곤 피격·적 처치·획득

| 상황 | 추가 연출 | 제한 |
|---|---|---|
| 플레이어 피격 | 캐릭터 밝기 또는 윤곽 변화 80~120ms, HP 변화 강조 | 무적 시간은 기존 판정 유지 |
| 큰 피해 | 선택적 카메라 흔들림 100~160ms, 최대 2~4 논리 px | 연속 흔들림 최소 간격 300ms |
| 일반 적 처치 | 축소·소멸 150~220ms, 잔광·파편 4~6개 | 사망 충돌체는 기존 규칙대로 제거 |
| 보스 처치 | 보스 중심 소멸·충격·보상 강조 700~1,000ms | 회피해야 하는 남은 위험을 가리지 않음 |
| 경험치 획득 | 실제 획득물 이동 경로를 따라 잔광·획득 반짝임 | 획득 반경·가속·판정 변경 금지 |
| 레벨업 | 드래곤 주변 링 350~500ms, UI 제목 150~220ms 등장 | 카드 선택·일시정지 처리는 기존 흐름 유지 |
| 실제 진화·최종 강화 | 속성 빛 500~800ms, 짧은 이름 표시 | 추가 진화 조건 또는 자동 지급 없음 |

피격 흰색 표시는 캐릭터 영역에 제한한다. 화면 전체를 반복적으로 하얗게 번쩍이지 않는다.

### 7.5 전투 가독성 우선순위

1. 적 공격 예고와 위험 영역.
2. 플레이어 실루엣·위치와 HP.
3. 적 투사체와 보스 패턴.
4. 플레이어 공격의 핵심 형태.
5. 불꽃·잔광·장식 파티클.

장식 효과가 예고 장판·적 탄환을 가리지 않게 한다. 플레이어 장식 효과는 위험 예고 아래에 그리거나 겹침 영역의 불투명도를 줄인다. 아군·적군 투사체를 속성 색 하나에만 의존해 구분하지 않는다.

보스 예고 장판은 기존 범위·지속시간·판정과 맞는 테두리·채움 진행을 표시한다. 예고 시간을 디자인 편의로 변경하지 않는다.

## 8. 10종 드래곤의 연출 확장 기준

공통 공격·피격·획득 연출 엔진에 속성 팔레트·입자·음색을 연결한다. 아래 항목은 기존에 해당 효과가 실제로 발생할 때만 재생하며 새 전투 효과를 추가하지 않는다.

| 드래곤 | 공격의 시각 언어 | 적중·상태 표현 | 과장 방지 |
|---|---|---|---|
| 레드 | 주황 화염·짧은 꼬리 | 불꽃·실제 화상·폭발 링 | 상시 큰 불기둥 금지 |
| 블루 | 청색 얼음·각진 결정 | 얼음 파편·실제 빙결 윤곽 | 미빙결 적에게 얼음 봉인 표시 금지 |
| 옐로 | 황금 번개·짧은 연결선 | 실제 연쇄 대상 사이의 번쩍임 | 연쇄하지 않은 적과 연결 금지 |
| 그린 | 녹색 독액·작은 방울 | 실제 중독의 입자·독구름 | 바닥·적 위험색과 혼동 방지 |
| 화이트 | 흰빛·금빛 중심 | 얇은 광선·실제 회복 반짝임 | 화면 전체 백색광 금지 |
| 블랙 | 짙은 보라 중심·명확한 밝은 가장자리 | 파편·암흑 파동 | 옐로 번개 형태와 구분 |
| 스톤 | 갈색 돌조각·먼지 | 실제 충격파·기절 아이콘 | 흔들림 반복 금지 |
| 윈드 | 민트색 곡선·짧은 바람 흔적 | 얇은 절삭 궤적 | 칼날 실루엣 보존 |
| 워터 | 청록 물방울·둥근 파문 | 실제 충격파·파도 | 얼음 결정과 구분 |
| 아케인 | 보라·분홍 마력 구체 | 실제 분열 지점과 추적 꼬리 | 분열 수만큼 무제한 입자 생성 금지 |

각 종은 낮은 공격 레벨, 다중 투사체 단계, 최종 강화 단계에서 확인한다. 현재 게임에서 레벨 효과가 옛 문서와 달라진 경우 최신 승인된 전투 데이터를 따른다.

## 9. 상자 개봉·보상 연출

이미 요청한 상자 연출에 **공통 상태·시간·상태별 효과·실제 결과 연결 기준**을 추가한다. 기존에 제작 요청한 상자 본체·뚜껑은 먼저 재사용 여부를 확인한다.

### 9.1 공통 연출 상태

```text
기존 구매/획득 처리의 결과 대기
    → 결과 확정
    → 상자 등장
    → 흔들림
    → 뚜껑 열림
    → 빛·입자
    → 실제 보상 카드 공개
    → 결과 목록
    → 닫기
```

연출 상태와 실제 보상 지급 상태를 분리한다. 화면을 흔들거나 뚜껑을 열었다는 이유로 지급 함수를 다시 호출하지 않는다.

### 9.2 대표 개봉 타임라인

대표 상자는 **총 2.5초**를 기준으로 구현한다. 아래 구간은 일부 효과가 겹쳐 진행된다.

| 시각 | 화면 동작 | 사운드·입력 |
|---|---|---|
| 0.00~0.20초 | 딤·중앙 패널 등장 | 배경 효과음 음량을 낮춤 |
| 0.15~0.40초 | 상자 0.85→1.0배 등장, 바닥 그림자 | 상자 착지음 |
| 0.40~0.80초 | 상자 좌우 ±3도, 2~3회 흔들림 | 금속·목재 흔들림음 |
| 0.80~1.10초 | 뚜껑 회전, 내부 빛 증가 | 개봉음 |
| 1.05~1.45초 | 등급별 광선·입자 확산 | 등급별 짧은 강조음 |
| 1.35~1.75초 | 보상 카드 0.8→1.0배 등장 | 보상 공개음 |
| 1.75~2.10초 | 실제 이름·등급·수량 표시 | 중복 전환 등 기존 결과 문구 연결 |
| 2.10~2.50초 | 효과 잦아듦, 결과 조작 가능 | 결과 목록·닫기 활성화 |

스킵은 결과가 확정된 뒤 표시한다. 스킵 시 결과 목록으로 바로 이동하며 구매·획득 처리를 반복하지 않는다. 연출을 완료할 때까지 불필요하게 유저를 묶어두지 않는다.

### 9.3 등급별 연출 차이

| 결과 등급 | 전체 길이 초기값 | 색·입자 초기값 | 강조 |
|---|---|---|---|
| 일반 | 1.5초 | 중립광·8~12개 | 짧은 공개음 |
| 희귀 | 2.0초 | 청색광·12~18개 | 얇은 광선 |
| 영웅 | 2.5초 | 보라광·18~24개 | 카드 윤곽 빛 |
| 전설 | 3.5초 | 금색광·24~32개 | 1회 충격 링·선택적 짧은 진동 |

대표 2.5초 타임라인을 등급 프리셋으로 조정한다. 상자 종류와 결과 등급은 별도 설정으로 두고 실제 결과보다 높은 등급의 연출을 보여주지 않는다. 복수 결과는 기존 결과 데이터 순서를 따르되, 대표 강조는 실제 최고 등급을 기준으로 한다.

### 9.4 개봉·지급 연결 검수

- 기존 보상 처리에서 **확정된 결과 ID**와 보상 목록을 연출에 전달한다.
- 결과 대기 중에는 개봉이 성공한 것처럼 카드·축하음을 먼저 보여주지 않는다.
- 실패 시 닫힌 상태 또는 오류 상태를 표시하고, 확정되지 않은 보상을 보여주지 않는다.
- 연출 도중 닫기·앱 백그라운드·재진입은 기존 지급 기록을 조회해 결과 화면을 복구한다.
- 지급 여부가 불명확한 네트워크 오류에서 새 구매를 자동 실행하지 않는다.
- 실제 지급이 이미 끝난 항목의 결과 버튼을 ‘받기’로 표기해 재지급처럼 보이게 하지 않는다. 이 경우 ‘확인’으로 표시한다.
- 스킵·연타·화면 닫힘·에셋 로드 실패가 실제 재화·보상에 영향을 주지 않아야 한다.

이 항목은 기존 지급 시스템의 화면 연결 기준이다. 기존에 요청한 서버·상점 기능을 다시 구현하라는 뜻이 아니다.

## 10. 사운드·진동·모션 설정

### 10.1 필요한 사운드 이벤트

| 이벤트 ID 예시 | 용도 | 재생 제한 초기값 |
|---|---|---|
| `ui.tap` | 일반 버튼 반응 | 동일 유형 60ms 이내 중복 억제 |
| `ui.tab` | 탭 이동 | 선택이 실제 변경될 때만 |
| `ui.confirm` | 실제 성공·확인 | 동일 결과당 1회 |
| `ui.error` | 처리 불가·실패 | 연타 시 반복 재생 제한 |
| `dragon.red.fire` | 화염탄 발사 | 한 공격 묶음당 1회, 탄환마다 재생하지 않음 |
| `combat.hit` | 적중 | 전역 50~80ms 최소 간격 |
| `combat.playerHit` | 플레이어 피격 | 실제 피격 이벤트 기준 |
| `combat.levelUp` | 레벨업·카드 화면 | 레벨업당 1회 |
| `chest.land/open/reveal` | 개봉 단계 | 개봉 세션 ID별 단계당 1회 |
| `reward.legendary` | 전설 보상 공개 | 실제 전설 결과당 1회 |

음색은 귀여운 판타지에 맞게 통일하고 버튼마다 서로 다른 게임의 효과음을 섞지 않는다. 반복 공격음은 짧고 피로하지 않게 조정한다. 유료·출처 불명 자료를 임의로 최종 에셋으로 취급하지 말고 각 파일의 제작·출처 정보를 기록한다.

### 10.2 믹싱과 사용자 환경

- BGM·UI·전투·보상 효과음의 논리 채널을 구분한다.
- 기존 음량 설정이 있으면 연결한다. 없으면 효과음·진동·모션 감소 설정을 이번 추가 UI 설정으로 제안한다.
- 효과음 기본 상대 크기: BGM 0.35, UI 0.45, 전투 0.35, 보상 0.6에서 청취 조정. 이는 최종 음량 표준이 아닌 믹서 초기값이다.
- 동시 효과음 수는 초기 8개로 제한하고, 중요한 피격·보상 음을 장식음보다 우선한다.
- 첫 사용자 입력 이후 오디오 활성화를 시도하며, 재생이 차단되어도 게임을 계속 사용할 수 있어야 한다.
- 백그라운드에서는 재생을 멈추거나 일시정지하고, 복귀 시 놓친 타격음을 한꺼번에 재생하지 않는다.
- 진동이 가능한 실행 환경에서만 사용한다. 미지원·꺼짐 상태에서 오류를 내거나 필수 피드백이 사라지면 안 된다.

### 10.3 모션 감소

- 모션 감소 시 화면 흔들림·연속 스케일 반동·배경 이동·강한 플래시를 제거한다.
- 팝업은 짧은 페이드로, 개봉은 간단한 카드 공개로 대체한다.
- 공격 예고·위험 범위·실제 결과 텍스트는 유지한다.
- 음소거·모션 감소·진동 끔 상태를 저장하고 앱 재실행 후 유지한다.

## 11. 에셋 제작·적용 명세

### 11.1 원칙

필요한 이미지를 전부 새로 만들기 전에 기존 제작 파일을 조사한다. 이미 요청된 상자 본체·뚜껑·드래곤·스킬 그림은 중복 제작하지 않는다. 아래 목록에는 **보유 여부·사용 가능 여부·추가 보완 필요 부분**을 표시한다.

### 11.2 신규 보완이 필요할 수 있는 자료

| 자료 | 작업 규격 제안 | 요구 사항 |
|---|---|---|
| 로비 배경 | 원본 1080×1920 이상, 실행용 압축본 별도 | 텍스트 없는 그림, 중앙 드래곤 자리와 상하 UI 여유 |
| 로비 전경·후경 | 분리 가능한 레이어 | 움직일 때 빈 틈·잘린 가장자리 노출 없음 |
| 드래곤 대기·날개 | 현재 원본을 기준으로 필요한 레이어·프레임 | 몸통 크기·중심·방향·발 위치 고정 |
| 화염 발사·적중 | 256×256 또는 512×512 원본 | 투명 배경, 중심점·유효 영역 메타데이터 |
| 공통 불꽃·빛·링 | 작은 재사용 텍스처 | 큰 불투명 사각형 흔적 없음 |
| 보상 카드 프레임 | 4등급 공통 비율 | 아이콘·이름·수량을 코드로 겹칠 공간 |
| 부족 효과음 | 짧은 원본과 실행 포맷 | 시작 공백·끝 클릭음 제거, 음량 일관성 |

단순 패널·버튼·탭·배지는 현재 렌더링 방식에서 선명하게 그릴 수 있으면 코드로 구현한다. 그림이 꼭 필요한 장식만 에셋으로 만든다. 이미지 제작 방식 자체를 특정 도구로 제한하지 않는다.

### 11.3 기존 상자 본체·뚜껑 자료의 추가 적용 기준

- 이미 요청된 **600×600 투명 캔버스** 파일을 우선 사용한다.
- 본체와 뚜껑은 같은 캔버스 크기·같은 좌표계로 유지하며 자동으로 각각 잘라 저장하지 않는다.
- 닫힌 상태에서 두 레이어를 포개면 정확히 하나의 상자가 되어야 한다.
- 뚜껑 회전축은 원본 캔버스 기준 정규화 좌표로 기록한다. 좌상단 `(0,0)`, 우하단 `(1,1)`을 사용한다.
- `lidPivot`, `lightOrigin`, `cardRevealOrigin`, `closedRotation` 값을 자료별로 기록한다. 실제 그림을 확인하지 않고 고정 좌표를 추정해 넣지 않는다.
- 열렸을 때 보이는 내부 면이 없다면 보완 에셋 또는 내부 어두운 면을 추가한다.
- 회전 중 뚜껑 뒷면·잘린 면이 보이면 단순 회전 방식으로 숨기지 말고 프레임·레이어 보완을 요청한다.
- 상자 외곽 그림자·광선·입자는 개봉 재생 코드에서 조절 가능하게 분리한다.

실제 경로는 기존 프로젝트에 맞춘다. 다음은 파일명 예시다.

에셋 목록에 `assetId`, 파일 경로, 실제 크기, 투명 여부, 중심점, 라이선스·제작 출처, 연결된 화면, 상태(최종/임시/미적용)를 기록한다. 최종 리소스와 임시 테스트 이미지를 같은 이름으로 혼용하지 않는다.

## 12. 실제 게임 코드에 연결하는 구현 기준

### 12.1 기존 로직과 표현의 분리

기존 게임 이벤트를 받아 표현 계층에서 연출한다. 시각 효과를 추가하면서 전투·경제 로직을 복사하지 않는다.

```text
기존 공격 이벤트 → 발사점 섬광·캐릭터 시각 반응·발사음
기존 투사체 위치 → 트레일 갱신
기존 적중 결과 → 실제 속성·치명타·피해량에 맞는 연출
기존 상태 변화 → 화상·빙결 등 표시 시작·종료
기존 획득 확정 → 수량·카드·결과 표시
```

### 12.2 데이터 계약 예시

아래 이름은 신규 파일명 지시가 아닌 연결 형태의 예시다. 실제 이벤트·클래스 이름에 맞춘다.

```ts
type Quality = 'low' | 'standard';

interface PresentationSettings {
  quality: Quality;
  reducedMotion: boolean;
  sfxEnabled: boolean;
  hapticsEnabled: boolean;
}

interface HitPresentation {
  eventId: string;
  sourceId: string;
  targetId: string;
  worldX: number;
  worldY: number;
  elementId: string;
  actualDamage: number;
  critical: boolean;
  visualRadius?: number; // 실제 판정·화면 좌표 변환에 근거
}

interface RewardReveal {
  operationId: string; // 기존 지급 처리의 ID를 재사용
  resultId: string;
  presentationPresetId: string;
  rewards: ReadonlyArray<{
    itemId: string;
    quantity: number;
    rarityId?: string;
  }>;
}
```

보상 결과를 연출 코드에서 다시 추첨하지 않는다. 동일 결과의 화면 재진입은 기존 결과를 다시 보여주는 동작이며 재지급 동작이 아니다.

### 12.3 재현·정리 규칙

- 장식 난수는 전투·소환 판정용 난수와 분리한다. 파티클 개수 변경 때문에 같은 시드의 전투 결과가 바뀌면 안 된다.
- 프레임 속도가 낮아져도 효과 시간이 누적되지 않도록 실제 경과시간으로 시각 상태를 갱신한다.
- 화면을 닫거나 다른 장면으로 이동하면 해당 장면의 이펙트·소리·타이머·리스너를 정리한다.
- 효과 생성은 재사용 가능한 풀·공통 관리 구조를 우선한다.
- 같은 이벤트가 중복 전달될 때 축하음·보상 연출이 계속 쌓이지 않도록 이벤트 ID·연출 세션 단위로 처리한다.
- 연출 실행 실패가 전투 진행·결과 수령·팝업 닫기를 막지 않게 한다.
- 연출 에셋은 처음 필요해지기 전에 준비하고, 준비 실패 시 단순 효과로 대체해 진행 가능하게 한다.

## 13. 성능·가독성·접근성

### 13.1 초기 성능 예산

다음 수치는 측정 후 조정할 초기 상한이다. 정확한 측정 기기와 빌드를 제출 자료에 적는다.

| 항목 | Standard | Low |
|---|---|---|
| 장식 파티클 동시 상한 | 160개 | 64개 |
| 피해 숫자 동시 상한 | 32개 | 16개 |
| 동시 장식 충격 링 | 12개 | 6개 |
| 배경 움직임 | 제한된 1~2종 | 정적 또는 1종 |
| 과도한 효과 발생 시 | 먼 장식·오래된 입자부터 생략 | 트레일·잔광 우선 단순화 |

이 상한은 실제 투사체·적·피해 판정 개수를 제한하지 않는다. 위험 예고·중요 상태 아이콘·플레이어 위치 표시는 장식 예산에서 제거하지 않는다.

### 13.2 목표 측정

- Standard: 정한 대표 모바일 기기에서 60FPS를 목표로 하고, 대표 전투 60초 구간의 프레임 시간 중앙값·95백분위·긴 멈춤을 기록한다. 95백분위 25ms 이내를 초기 목표로 한다.
- Low: 30FPS를 목표로 같은 구간을 측정하며 95백분위 40ms 이내를 초기 목표로 한다.
- 같은 기기·시드·성장 조건으로 적용 전후를 비교한다. 원래 성능이 목표에 못 미치면 기존 병목과 추가 연출 비용을 구분한다.
- 10분 연속 플레이, 반복 개봉 20회, 화면 왕복 30회 후 이펙트·오디오·리스너 수가 지속 증가하지 않는지 확인한다.
- 처음부터 모든 에셋을 한꺼번에 읽어 초기 로딩을 늘리지 말고 실제 실행 경로에 맞춰 로드한다.
- 타깃 기기가 제공되지 않으면 개발자가 사용한 기기를 명시하고, 미검수 기기를 통과한 것으로 보고하지 않는다.

### 13.3 가독성 검사

- 큰 글자 설정과 긴 한국어 이름에서도 버튼·가격·등급 문구 겹침 없음.
- 터치 조작을 방해하는 효과 레이어 없음.
- 색을 구분하기 어려워도 등급·선택·위험 상태를 텍스트·형태로 이해 가능.
- 빠른 연속 전면 플래시 없음. 화면 흔들림과 강한 모션은 끌 수 있음.
- 음소거에서도 성공·실패·피격·보상 결과를 알 수 있음.
- 외부 키보드를 지원하는 화면에서는 포커스·팝업 닫힘 후 복귀를 확인한다.

## 14. 검수 시나리오와 완료 기준

### 14.1 개발자가 제출할 영상

### 14.4 시각 검수에서 다시 수정할 상황

- 드래곤·패널·아이콘이 서로 다른 화풍으로 보인다.
- 드래곤 전체를 크게 늘이거나 찌그러뜨려 움직임을 대신한다.
- 화면 전체가 반짝여 어떤 버튼이 중요한지 알기 어렵다.
- 불꽃과 보상 효과가 글자·적 공격 예고를 가린다.
- 개봉 그림만 바뀌고 뚜껑·빛·카드·소리 연결이 없다.
- 서버 오류인데 성공 연출을 보여주거나, 연출을 끝내야 실제 보상이 지급된다.
- 대표 화면만 예쁘고 기존 게임에서 그 화면으로 진입할 수 없다.
- 임시 이미지·음성·미연결 버튼이 남아 있는데 완료로 보고한다.
